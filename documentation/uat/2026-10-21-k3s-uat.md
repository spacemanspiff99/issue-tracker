## Ground rules

- UAT only. Every command names `issue-tracker-uat` or the `uat` argument. Production
  (`issue-tracker`) is touched only in [Exit](#exit-criteria-for-promoting-to-production), after
  you approve it.
- **Deleting the namespace is the point of this drill and is allowed for `issue-tracker-uat`
  only**: it proves a clean install is repeatable. It is not a reset (resets follow
  `manual-uat.md`, "UAT reset"), and never run it for `issue-tracker`.
- **Precondition:** issue 0048 (the shared lock, #30, `50b98cd`) is on `main`, and `main` stays
  frozen from run 1 until promotion. One digest `D` for both runs: if `main` moves between runs,
  the pipeline builds a new digest, R3 of run 2 refuses, and you start again at run 1.
- Never `alembic downgrade`. Never delete a PVC in `issue-tracker`.
- Close every MCP client that points at UAT before any pipeline dispatch, before R6–R8, and
  before deleting the namespace (the stdio server holds its own DB session).
- **Restore lock (`issue-tracker-restore-lock`, issue 0048).** `deploy.sh` and `restore.sh` share
  one ConfigMap lock. It applies from `main`, not from the image: the pipeline runs `deploy.sh`
  from its checkout, and you run `restore.sh` from yours. The holder in `data.job` is
  `deploy-<sha12>-<ts>` for a deploy and `issue-tracker-restore-<ts>` for a restore. A second
  holder is refused with:

  ```
  refusing: could not take the restore lock (ConfigMap issue-tracker-restore-lock in issue-tracker-uat): a restore or another deploy holds it, or the API failed.   (deploy.sh)
  refusing: could not take the restore lock (ConfigMap issue-tracker-restore-lock in issue-tracker-uat): a restore or deploy holds it, or the API failed.           (restore.sh)
  ```

  Start R6 and R8 only after the **whole** pipeline run has finished (including the browser
  suite). **Before every dispatch (R3, R7, R9, Exit) and every restore (R6, R8)** check:

  ```bash
  $K get configmap issue-tracker-restore-lock
  #   Error from server (NotFound): configmaps "issue-tracker-restore-lock" not found
  ```

  **Leftover lock** (it exists but nothing should be running): read the holder, confirm nothing
  runs, then delete it.

  ```bash
  $K get configmap issue-tracker-restore-lock -o jsonpath='{.data.job}{"\n"}'   # deploy-... or issue-tracker-restore-...
  $K get jobs,pods     # no backup-predeploy, migrate or restore Job active; no such pod Running
  $K delete configmap issue-tracker-restore-lock                                 # only if both checks are clean
  ```
- Never paste a password, token, kubeconfig or Secret value into this file.

### R1. Delete the UAT namespace

This is the deliberate drill exception to `k3s.md`'s "never delete a PVC or namespace to reset":
UAT only, to prove a clean install. When the namespace exists, copy its newest dumps off first.

```bash
NS=issue-tracker-uat
KUBECONFIG=$ADMIN_KUBECONFIG kubectl get namespace "$NS" -o name            # namespace/issue-tracker-uat (or NotFound on a first-ever run)
# Only if it exists (with the UAT kubeconfig):
deployment/k8s/backup-files.sh uat get-latest ~/uat-backups/$(date -u +%Y%m%d)
#   newest daily, pre-migration and pre-restore dumps copied into ~/uat-backups/<date>/
if [ "$NS" = issue-tracker-uat ]; then
  KUBECONFIG=$ADMIN_KUBECONFIG kubectl delete namespace "$NS" --wait=true --timeout=300s
else
  echo "wrong namespace"; false
fi
#   namespace "issue-tracker-uat" deleted
KUBECONFIG=$ADMIN_KUBECONFIG kubectl get namespace "$NS"
#   Error from server (NotFound): namespaces "issue-tracker-uat" not found
KUBECONFIG=$ADMIN_KUBECONFIG kubectl get pv | grep 'issue-tracker-uat/' || echo "no UAT PVs left"
#   no UAT PVs left   (a Released PV with policy Retain is a leftover: note it; it is not reused)
```
